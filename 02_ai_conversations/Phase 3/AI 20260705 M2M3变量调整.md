# 问题 2：M3 的 core vs full / portwatch / tanker

## 1. M3 各个变量臂的含义

M3 的不同变量臂不是同一种变量集，而是对航运模态的不同切法。

这些变量臂主要由：

```text
robustness_m3.py::select_m3_arm
```

控制。


| M3 臂           | 选列逻辑                                      | 列数  | XGB RMSE | XGB CW_p |
| -------------- | ----------------------------------------- | --- | -------- | -------- |
| core（主模型）      | 人工精选：GFW 6×4 + PW 咽喉 6×2 + PW 港口 2        | 38  | 4.476    | 0.096 ✗  |
| full           | 所有 M3 航运列，包括 PortWatch 64 列 + GFW 49 列    | 113 | 4.429    | 0.0002 ✅ |
| portwatch-only | 只保留列名为 `pw_*` 的 PortWatch 特征，日频、精度较高      | 64  | 4.356    | 0.0003 ✅ |
| tanker-only    | 只保留列名中包含 `tanker` 的油轮专属列，几乎全部来自 PortWatch | 多列  | 4.343    | 0.0018 ✅ |


另外还有两个对照臂：


| 对照臂           | 含义                                    |
| ------------- | ------------------------------------- |
| gfw-only      | 只保留 `gfw_*` 月频航运列                     |
| gfw-aggregate | 只使用 1 个派生汇总列：`gfw_all_activity_zmean` |


---



## 2. core 的问题：人工精选反而最弱

当前主模型使用的是：

```text
M3 core
```

它的设计逻辑是人工挑选“高价值核心航运变量”。

具体包括：

```text
GFW 6×4
PortWatch 咽喉 6×2
PortWatch 港口 2
```

总共 38 列。

但实测结果显示：

```text
M3 core XGB RMSE = 4.476
M3 core XGB CW_p = 0.096
```

也就是说，core 在 XGB 下：

- RMSE 高于 full / portwatch-only / tanker-only；
- CW_p 大于 0.05；
- 没有达到统计显著；
- 是当前几个主要 M3 臂里表现最弱的默认设定。

因此，core 虽然在设计上是“人工精选核心”，但实证上并不是最优。

更准确地说：

> core 精选可能丢掉了 XGB 能够利用的非线性航运信号。

---



## 3. full / portwatch / tanker 为什么更好？



### 3.1 full：完整保留航运模态信息

`full` 使用所有 M3 航运列：

```text
PortWatch 64 列 + GFW 49 列 = 113 列
```

结果为：

```text
M3 full XGB RMSE = 4.429
M3 full XGB CW_p = 0.0002
```

这说明完整航运变量集合中确实存在显著预测信号。

full 的意义是：

> 航运模态中的有效信息可能分散在多个细分变量中，人工压缩成 core 后反而损失信息。

---



### 3.2 portwatch-only：日频 AIS 贸易指标更干净

`portwatch-only` 只保留：

```text
pw_*
```

也就是 PortWatch 特征。

结果为：

```text
M3 portwatch-only XGB RMSE = 4.356
M3 portwatch-only XGB CW_p = 0.0003
```

它比 core 明显更好。

原因可能是：

- PortWatch 是日频数据；
- 时间分辨率高于 GFW 月频数据；
- 变量更接近贸易和港口 / 咽喉道活动；
- 数据语义更清楚；
- 噪声相对更少。

因此，portwatch-only 可以被解释为：

> 更高频、更贴近贸易流的航运指标，比人工混合后的 core 更有效。

---



### 3.3 tanker-only：油轮专属信号最强

`tanker-only` 只保留列名中包含：

```text
tanker
```

的油轮专属变量。

结果为：

```text
M3 tanker-only XGB RMSE = 4.343
M3 tanker-only XGB CW_p = 0.0018
```

这是几个主要 M3 臂中 RMSE 最低的配置。

它的机制解释也最清楚：

> 原油价格最相关的航运信号不是所有船舶活动，而是油轮专属的过境计数、运力变化和关键咽喉道活动。

这些信号对应：

- 霍尔木兹海峡；
- 苏伊士运河；
- 曼德海峡；
- 好望角绕行；
- 红海航运扰动；
- 原油运输链条变化。

因此，tanker-only 是 M3 中机制最强的子集。

---



## 4. M3 和 M2 的方向正好相反

这是这轮结果中非常重要的发现。

### 4.1 M2：少而精最好

M2 遥感模态的结果显示：

```text
M2 literature 4 列显著
M2 full 55 列反而被噪声淹没
```

也就是说，M2 的方向是：

> 遥感变量需要少而精，精选和去噪比全量拼接更有效。

---



### 4.2 M3：core 精选反而不如 full / portwatch / tanker

M3 航运模态的结果则相反。

```text
core 不显著
full 显著
portwatch-only 显著
tanker-only 显著
```

也就是说，M3 的方向是：

> 航运变量中有用信号可能分散在更多细分列里，人工 core 精选反而丢掉了 XGB 能够利用的信息。

这说明：

```text
M2：少而精更好
M3：人工 core 精选反而次优
```

这两个模态的最佳处理方式并不一样。

---



## 5. 对 RQ2 的意义

这个结果非常适合支持 RQ2。

RQ2 关注的是：

```text
扁平融合 vs 模态感知融合
```

当前结果说明：

> 不同模态的有效信息结构不同，不能用同一种人工筛选逻辑或简单 flat fusion 统一处理。

具体来说：

- M2 遥感模态需要精选和去噪；
- M3 航运模态需要保留更丰富的 PortWatch / tanker 信息；
- core 这种人工精选并不稳定；
- full / portwatch / tanker 在 XGB 下显著，说明航运模态存在非线性信号；
- 最优子集因模型、因模态而异。

因此，这不是一个简单的“变量多一点或少一点”的问题，而是：

```text
不同模态的信息结构不同；
flat fusion 很难自动处理这种差异；
需要模态感知的表示级融合。
```

---



## 6. 可以写进论文的核心表述

可以写成：

> M3 robustness results reveal a pattern opposite to M2. While M2 benefits from a small and denoised literature-based subset, M3 does not benefit from the manually selected core tier. Instead, the full, PortWatch-only, and tanker-only specifications all outperform the core setting and pass the Clark-West test under XGBoost. This suggests that useful shipping signals are distributed across a broader set of high-frequency and tanker-specific variables, and that manual feature selection may discard nonlinear information exploitable by tree-based models. The contrast between M2 and M3 provides direct evidence that the optimal feature subset is both model-dependent and modality-dependent, reinforcing the limitations of flat feature fusion and motivating modality-aware representation learning.

中文版本：

> M3 的稳健性结果呈现出与 M2 相反的模式。M2 中，少量精选和去噪后的遥感变量最有效；但 M3 中，人工精选的 core tier 反而表现最弱。相比之下，full、portwatch-only 和 tanker-only 在 XGB 下均优于 core，并通过 Clark-West 显著性检验。这说明有用的航运信号可能分散在更广泛的高频 PortWatch 变量和油轮专属变量中，人工筛选可能丢弃了树模型能够利用的非线性信息。M2 与 M3 的差异表明，最优变量子集同时依赖模型和模态，这正是 flat fusion 的局限，也进一步支持使用模态感知的表示级融合方法。

---



## 7. 一句话总结

M3 不建议继续把 `core` 当作唯一主模型。

更合理的结论是：

```text
M3 的最优变量集因模型和模态机制而异；
core 是人工精选但实证最弱；
full / portwatch-only / tanker-only 更能保留 XGB 可利用的航运信号；
这正好证明 flat fusion 对变量选择非常敏感，因此需要模态感知融合。
```






# 问题 2：M3 变量改成什么最好？

## 一、核心结论

M3 变量没有单一“最优变量集”。

更准确的结论是：

> M3 的最优变量集因模型而异；当前 `core` 不是最优，反而是最弱的默认设定。

也就是说，不能简单说：

```text
M3 应该固定用 core
```

或者：

```text
M3 应该固定用 full
```

因为不同算法对航运变量的吸收能力不同：

- XGB 更能利用高维、非线性、细分航运变量；
- Ridge 更偏好低维、稳定、聚合后的航运信号。

---

## 二、M3 LOCHO 实测结果

基准模型：

```text
M1_XGB RMSE = 4.368
```

M3 LOCHO 结果如下：

| M3 臂 | 列数 | XGB RMSE | XGB CW_p | Ridge CW_p |
|---|---:|---:|---:|---:|
| core（当前主模型） | 38 | 4.476 | 0.096 ✗ | 0.289 ✗ |
| full | 113 | 4.429 | 0.0002 ✅ | 0.264 ✗ |
| portwatch-only | 64 | 4.356 | 0.0003 ✅ | 0.098 ✗ |
| tanker-only | 多 | 4.343 | 0.0018 ✅ | 0.091 ✗ |
| gfw-aggregate | 1 | 4.344 | 0.094 | 0.047 ✅ |

---

## 三、关键事实

### 3.1 M3 没有单一最优变量集

从 XGB 看，表现最好的 M3 子集是：

```text
tanker-only ≈ gfw-aggregate ≈ portwatch-only
```

具体结果为：

| XGB 配置 | RMSE |
|---|---:|
| tanker-only | 4.343 |
| gfw-aggregate | 4.344 |
| portwatch-only | 4.356 |

从 Ridge 看，表现最好的配置是：

```text
gfw-aggregate
```

它是唯一一个在 Ridge 下超过 M1 且显著的配置：

```text
gfw-aggregate Ridge RMSE = 4.246
gfw-aggregate Ridge CW_p = 0.047
```

因此，M3 的核心结论不是“哪个变量集绝对最好”，而是：

> 最优 M3 子集依赖模型结构。

---

### 3.2 当前 core 是最弱的默认设定

当前主模型使用的是：

```text
M3 core = 38 列
```

但它在 XGB 下的表现并不好：

```text
M3 core XGB RMSE = 4.476
M3 core XGB CW_p = 0.096
```

也就是说，它既不是 RMSE 最优，也没有通过 5% 显著性检验。

相比之下：

| 配置 | XGB RMSE | XGB CW_p |
|---|---:|---:|
| core | 4.476 | 0.096 ✗ |
| full | 4.429 | 0.0002 ✅ |
| portwatch-only | 4.356 | 0.0003 ✅ |
| tanker-only | 4.343 | 0.0018 ✅ |
| gfw-aggregate | 4.344 | 0.094 |

这说明：

> 人工精选出来的 core tier 反而可能丢掉了对 XGB 有用的航运信息。

因此，继续把 `core` 作为唯一主模型会比较危险。

---

## 四、建议方案

## 方案 A：主基线改用 full，core 等作为稳健性分析

这是最推荐、也最诚实的方案。

### 方案 A 的设置

主 M3 使用：

```text
M3 full = 113 列
```

然后把以下配置全部作为 LOCHO / 稳健性分析：

- core
- portwatch-only
- tanker-only
- gfw-aggregate
- 其他航运子集

### 方案 A 的理由

`full` 在 XGB 下显著：

```text
M3 full XGB CW_p = 0.0002
```

说明完整航运变量集合中确实存在预测信号。

同时，`full` 的 Ridge 表现较差，也有解释价值：

```text
M3 full Ridge CW_p = 0.264
```

这可以说明：

> 高维航运变量中有信号，但线性模型难以有效吸收，容易受到共线性和噪声影响；XGB 更能捕捉其中的非线性结构。

因此，方案 A 的叙事最完整：

> M3 并不存在单一最优子集，最优配置依赖模型结构；人工精选的 core 反而次优。这正好说明 flat fusion 对变量筛选和模型结构高度敏感，从而支持 RQ2：需要模态感知融合，而不是简单人工拼接变量。

### 方案 A 的论文卖点

可以写成：

> M3 robustness results show that the predictive value of shipping features is highly subset- and model-dependent. While the manually selected core tier is not significant under XGB, the full, portwatch-only, and tanker-only variants remain strongly significant. This suggests that hand-crafted feature selection may discard useful nonlinear shipping signals, providing further motivation for modality-aware representation learning.

中文解释就是：

> M3 的预测价值高度依赖变量子集和模型类型。当前人工精选的 core tier 并不显著，但 full、portwatch-only、tanker-only 仍然显著。这说明人工特征筛选可能丢失非线性航运信号，因此更需要模态感知的表示学习。

---

## 五、方案 B：主基线改用 portwatch-only

如果你希望主模型更精悍，而不是使用 113 列 full，那么可以改用：

```text
M3 portwatch-only = 64 列
```

### 方案 B 的理由

`portwatch-only` 的优势是：

1. 数据来源更权威；
2. 变量语义更清晰；
3. 特征数量适中；
4. XGB 显著；
5. RMSE 接近最优。

具体结果：

```text
M3 portwatch-only XGB RMSE = 4.356
M3 portwatch-only XGB CW_p = 0.0003
```

它的表现接近 tanker-only 和 gfw-aggregate，但比 full 更简洁，也比 core 更有统计支撑。

### 方案 B 的叙事逻辑

方案 B 不建议用“挑最优”来解释，而是用“数据质量”来解释。

可以写成：

> PortWatch-based features are selected as the main M3 specification because they provide official AIS-based trade and shipping indicators with higher temporal resolution and clearer economic interpretation than broader GFW monthly aggregates.

中文解释就是：

> 选择 PortWatch 作为主 M3 设定，并不是因为它事后表现最好，而是因为它具有更高的数据质量、更明确的经济含义和更合适的时间分辨率。

这样可以避免被质疑：

```text
是不是因为结果好才选它？
```

---

## 六、不建议继续使用 core 作为唯一主模型

不建议继续把：

```text
M3 core = 38 列
```

作为唯一主模型。

原因很简单：

```text
M3 core XGB RMSE = 4.476
M3 core XGB CW_p = 0.096
```

它在 XGB 下：

- 不是 RMSE 最优；
- 没有通过显著性检验；
- 明显弱于 full / portwatch-only / tanker-only；
- 也没有 Ridge 下的优势。

如果继续保留 core，就必须在正文中明确写出：

> core tier 是一个人工精选的简化设定，但实证结果显示，它对 XGB 来说反而次优，说明人工筛选可能丢弃了有用的航运信号。

否则，读者可能会质疑：

> 为什么主模型要选一个表现最弱的 M3 配置？

---

## 七、机制解释：为什么 tanker-only 很重要？

`tanker-only` 的表现最强之一：

```text
M3 tanker-only XGB RMSE = 4.343
M3 tanker-only XGB CW_p = 0.0018
```

这说明，航运模态里最有价值的信号很可能不是泛泛的“船舶活动”，而是更贴近原油运输链条的油轮专属指标。

这在机制上是合理的。

油轮活动直接对应：

- 原油运输；
- 咽喉道通行；
- 供应链扰动；
- 红海绕行；
- 霍尔木兹海峡风险；
- 苏伊士 / 曼德海峡拥堵；
- 好望角绕行带来的运输距离和成本变化。

因此，`tanker-only` 可以作为 M3 中机制最强的稳健性亮点。

不过，它不一定要作为主模型。

更合理的处理是：

```text
主模型：full 或 portwatch-only
机制稳健性：tanker-only
```

这样既有主结果的完整性，也有机制解释的清晰性。

---

## 八、最终建议

### 推荐选择

我建议采用：

```text
方案 A：M3 主基线改用 full，其他子集作为稳健性分析。
```

理由是：

1. full 能最完整地代表航运模态；
2. full 在 XGB 下显著；
3. full 与 Ridge 的差异可以解释“高维航运变量对模型结构敏感”；
4. core 表现弱，正好作为人工精选次优的证据；
5. portwatch-only / tanker-only / gfw-aggregate 可以作为稳健性和机制补充；
6. 这个结论最能支持 RQ2。

---

## 九、可以写进论文的结论表述

可以写成：

> The M3 robustness results indicate that there is no single universally optimal shipping feature set. The best-performing subset depends strongly on model architecture. Under XGBoost, tanker-only, GFW aggregate, and PortWatch-only variants achieve the lowest RMSEs, while under Ridge the one-dimensional GFW aggregate is the only configuration that slightly outperforms M1 and passes the CW test. In contrast, the manually selected core tier performs weakest and is not significant under XGBoost. This suggests that hand-crafted feature selection may discard useful nonlinear shipping signals, while high-dimensional shipping information remains difficult for linear models to absorb. These findings reinforce the limitation of flat feature fusion and motivate modality-aware representation learning.

中文版本：

> M3 稳健性结果表明，航运模态不存在一个对所有模型都最优的变量集。最优子集明显依赖模型结构：在 XGB 下，tanker-only、GFW aggregate 和 PortWatch-only 的 RMSE 最低；而在 Ridge 下，只有一维的 GFW aggregate 略微超过 M1 并通过 CW 检验。相比之下，人工精选的 core tier 表现最弱，且在 XGB 下不显著。这说明人工特征筛选可能丢弃了有用的非线性航运信号，而高维航运信息又难以被线性模型有效吸收。因此，M3 结果进一步说明 flat feature fusion 的局限，并强化了使用模态感知表示学习的必要性。

---

## 十、一句话总结

M3 变量不应该继续只用当前的 `core`。

最推荐的处理是：

```text
主模型用 full；
core / portwatch-only / tanker-only / gfw-aggregate 全部作为稳健性；
重点论证“最优航运子集因模型而异，人工精选并不稳定”，从而支持 RQ2。
```

如果想要一个更精悍、语义更干净的主模型，则可以选择：

```text
portwatch-only
```

但不建议继续把：

```text
core
```

作为唯一主模型。
