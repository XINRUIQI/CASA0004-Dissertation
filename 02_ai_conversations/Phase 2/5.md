
# 4. 特别注意事项

## 4.1 GPR 与文本模态的概念重叠

`gpr` 是根据新闻文本构建的聚合指数，因此概念上与文本模态存在一定重叠。

但按照当前研究设计：

```text
GPR 保留在 M1。
```

原因是：

- GPR 已经是外部研究机构发布的结构化指数；
- 它不是本项目自行构建的新闻文本嵌入或 LLM 事件变量；
- 它代表一个具有明确经济含义的地缘政治风险状态变量；
- 可以作为预防性需求和外部风险的传统结构化代理。

后续文本模态应主要包含：

- 原始新闻事件；
- 供应中断事件；
- 制裁事件；
- 冲突事件；
- OPEC 决策文本；
- 新闻情绪；
- LLM 分类结果。

---

## 4.2 `futures_spread` 的近似性质

当前 `futures_spread` 定义为：

```math
futures\_spread_t
=
\log(BZ=F_t)-\log(BrentSpot_t)
```

其中：

- `BZ=F` 是 Yahoo Finance 的 Brent 连续近月合约；
- `BrentSpot` 是本地 Brent 现货价格。

该变量可以作为市场紧张程度和期货结构的近似代理，但并不是严格意义上的固定期限价差。

更严格的期限结构应使用：

```text
Brent front-month
Brent 3-month
Brent 6-month
Brent 12-month
```

并构建：

```math
Spread_t^{1-6}
=
\log(F_t^{1m})-\log(F_t^{6m})
```

因此论文中应明确说明：

```text
The futures spread used in the current pipeline is an approximate spot–front-
month spread constructed from a continuous Brent futures series, rather than a
constant-maturity futures-curve measure.
```

# 10. M1 样本损失问题

## 10.1 问题来源

当前 `data_loader` 使用：

```python
dropna()
```

但两个 M1 核心变量在研究期早期不存在：

```text
ovx：从 2007-05 开始
futures_spread：从 2007-08 开始
```

因此，M1 只有在 2007-08 以后才能满足所有核心变量均非空。

---

## 10.2 样本变化

完整周度时间索引：

```text
1043 周
2006-01 至 2025-12
```

执行 `dropna()` 后的 M1 有效样本：

```text
957 周
2007-08 至 2025-12
```

样本损失：

```text
1043 - 957 = 86 周
```

约损失：

```text
1 年 8 个月
```

---

## 10.3 三种处理选择

### 选择 A：接受较晚起点

```text
M1 统一从 2007-08 开始
```

优点：

- 不需要人为填补；
- 变量定义最干净；
- 所有模型使用真实可观测数据；
- 消融实验容易保证共同样本；
- 仍然保留 957 个周度样本。

这是当前最推荐的核心方案。

---

### 选择 B：对早期数据进行回填

可能做法包括：

- 用 VIX 代理 OVX；
- 对期货价差进行模型估算；
- 用常数或历史均值填补；
- 增加 missingness flag。

但不建议简单使用：

```python
ffill()
```

原因是 OVX 和期货价差在研究起点之前根本没有历史记录，无法通过真正的前向填充得到值。

从未来向过去执行：

```python
bfill()
```

则会直接产生前视偏差，因此不可使用。

如果使用 VIX 代理早期 OVX，也不能把二者无标记地拼接成同一个原始变量。

---

### 选择 C：把 OVX 或期货价差移出核心 M1

例如：

```text
OVX → VIX
futures_spread → 从核心集降级为扩展变量
```

优点：

- 可以保留 2006 年开始的完整样本。

缺点：

- 会削弱 M1 的石油市场针对性；
- 与精读后的机制化变量设计不完全一致；
- VIX 对应的是广义股票市场风险，而不是石油特定不确定性。

因此不建议作为主模型，但可以作为稳健性模型。

---

核心实验：

```text

```

稳健性实验：

# 11. 加入随机游走与 Naive 基准

## 11.1 是否需要 M0

需要设置 M0。

复杂模型必须首先证明其预测表现优于简单、透明且强有力的基准。

M0 可以包含以下基准：

| 基准 | 定义 |
|---|---|
| Majority-class baseline | 始终预测训练集中占比最高的方向 |
| Historical probability baseline | 根据训练窗口中的上涨概率输出固定概率 |
| No-change price forecast | 预测下一期价格等于当前价格 |
| Random walk | `p_(t+1) = p_t + ε_(t+1)` |
| Directional persistence | 下一周方向等于本周方向 |
| Recent-window majority | 使用最近若干周中出现次数最多的方向 |
| Logistic price-only | 仅使用 Brent 自身滞后价格和收益率 |

---

## 11.2 分类任务中的随机游走基准

当前目标是：

```text
target_brent_direction_next_1w
```

因此严格的随机游走价格预测：

```math
\hat{P}_{t+1}=P_t
```

意味着预测收益率为 0。

如果分类标签只有：

```text
1 = 上涨
0 = 下跌
```

则随机游走本身无法自然映射为上涨或下跌。

可采用以下处理方式之一。

### 方法一：No-change 单独作为价格基准

在连续价格或收益率预测任务中评估随机游走：

```math
\hat{P}_{t+1}=P_t
```

并报告：

- MAE；
- RMSE；
- MAPE；
- Directional Accuracy。

### 方法二：方向持续性基准

对于二分类任务，使用：

```math
\hat{y}_{t+1}=y_t
```

即：

```text
本周上涨 → 预测下周上涨
本周下跌 → 预测下周下跌
```

### 方法三：多数类基准

始终预测训练窗口中的多数类别。

该基准可以防止 Accuracy 因类别不平衡而显得虚高。

---

## 11.3 推荐的 M0 结构

```text
M0-A：Majority class
M0-B：Historical probability
M0-C：Directional persistence
M0-D：Price-only logistic regression
M0-E：Random-walk price forecast（连续任务）
```

所有 M1、M2、M3 和 M4 模型都应与相应 M0 基准比较。

# 12. M1 待讨论问题

## 12.1 是否需要 M0 模型？

建议答案：

```text
需要。
```

理由：

- 随机游走和不变预测是油价预测中的强基准；

- M0 可以帮助识别 Accuracy 是否只是来自类别不平衡；
- 后续 DM 检验需要明确的基准预测序列。

## 12.3 M1 应使用小规模核心集还是大候选池？

研究问题：

```text
Should M1 retain a relatively small and economically structured core set of
variables, or should I begin with a larger candidate pool and conduct dynamic
feature selection within each training window?
```

推荐采用双层设计。

### 主规格：小规模、机制明确的核心变量集

核心 M1 保留当前 10 个机制化变量。

优点：

- 文献依据清晰；
- 经济解释明确；
- 减少共线性；
- 降低过拟合风险；
- 有利于 SHAP 解释；
- 消融实验更容易解释；
- 适合约 957 个周度样本的规模。

### 扩展规格：更大的候选池与窗口内动态筛选

将已降级变量保留在扩展候选池，例如：

- `vix`；
- `dollar_index`；
- `crude_production`；
- `refinery_utilisation`；
- `sp500_return_pct`；
- `treasury_10y`；
- `crude_imports`；
- `crude_exports`。

在每个训练窗口内部执行：

- LASSO；
- Elastic Net；
- mutual information；
- permutation importance；
- Boruta；
- XGBoost gain；
- stability selection。

重要原则：

```text
特征筛选只能在训练窗口内部完成。
```

不能使用完整数据集或测试集选择变量，否则会发生选择泄漏。

### 推荐结论

```text
核心结论基于固定的机制化 10 变量 M1；
动态特征筛选作为扩展和稳健性分析，而不是替代核心 M1。
```

这样既保留经济理论结构，又检验是否存在随时间变化的有效预测变量。

# 13. M2 待讨论问题

## 13.1 是否需要使用 Sentinel-2？

Sentinel-2 不应仅因为“属于遥感数据”而自动进入最终模型。

是否保留 S2，应取决于它能否提供独立且可验证的经济代理。

可能的 S2 指标包括：

- NDVI；
- NDWI；
- NDBI；
- BSI；
- clear observation count；
- cloud fraction。

但对于石油储运和港口活动，S2 存在以下问题：

- 云覆盖高；
- 有效观测不连续；
- 周频覆盖不足；
- 光谱指数与石油活动之间的机制可能较弱；
- AOI 内土地覆盖变化缓慢；
- 云量指标可能主要反映天气，而不是经济活动。

推荐将 S2 分为两类。

### 核心质量变量

- `s2_clear_obs_count`
- `s2_cloud_fraction`

这些变量用于控制遥感观测质量，而不是直接解释经济活动。

### 可选机制变量

只有在机制验证通过后，才保留：

- NDWI；
- NDBI；
- 其他与储罐、港口或工业活动有直接关系的指标。

因此建议：

```text
S2 不作为必选核心模态；
NTL 是 M2 的核心遥感代理；
S2 作为辅助和稳健性特征。
```

---

## 13.2 是否需要进行机制验证？

需要。

机制验证与最终预测评估解决的是不同问题。

### 机制验证回答

```text
遥感或航运变量是否确实反映其声称代表的现实经济活动？
```

### 预测实验回答

```text
这些变量是否提高了下一周油价预测表现？
```

两者都需要。

即使某个变量提高预测表现，如果没有机制验证，也可能只是：

- 时间趋势；
- 季节性；
- 云量模式；
- 数据覆盖变化；
- 地区固定差异；
- 偶然相关；
- 代理了其他市场变量。

# 16. 跨层模型比较与样本窗口问题

## 16.1 当前问题

M1 和 M2 可以使用较长的历史数据。

但 M3 或更高层模态的完整覆盖可能仅从 2019 年开始。

因此可能出现：

```text
M1 / M2：
较长训练和测试样本

M3 / M4：
仅使用 2019 年以后样本
```

若测试集中对齐后只有约：

```text
N ≈ 54
```

则不能直接把两个不同时间窗口上的指标视为同一条件下的模型优劣。

---

## 16.2 必须区分两类结果

### 全样本性能

每个模型使用其可获得的最长时间范围。

该结果回答：

```text
在每种数据模态的实际历史覆盖条件下，模型能够达到什么性能？
```

但不能严格用于判断加入模态的因果增量价值。

### 共同样本性能

将 M1、M2、M3 和 M4 全部限制在相同时间范围，例如：

```text
2019 年以后
```

该结果回答：

```text
在完全相同的训练、验证和测试日期上，加入新模态是否提高预测性能？
```

消融实验的核心结论必须基于共同样本性能。

---

## 16.3 推荐报告结构

| 比较类型 | 时间范围 | 用途 |
|---|---|---|
| M1 全样本 | M1 可用的最长时期 | 报告传统变量模型的最大样本表现 |
| M2 全样本 | M2 可用的最长时期 | 报告遥感模型的最大样本表现 |
| M3/M4 全样本 | 航运数据可用时期 | 报告航运模型的实际可用表现 |
| 共同样本消融 | 所有模态共同覆盖期 | 判断增加模态后的增量价值 |

---

## 16.4 DM 检验要求

Diebold–Mariano 检验只能在以下条件下进行：

- 两个模型预测完全相同的目标日期；
- 预测步长相同；
- 使用相同测试样本；
- 损失函数定义相同；
- 预测序列长度一致。

因此：

```text
不能直接对 M1 全样本预测和 M3 仅 2019+ 的预测执行 DM 检验。
```

正确做法是：

```text
截取 M1 在 M3 测试日期上的预测
        ↓
与 M3 同日期预测进行比较
        ↓
在对齐预测误差序列上执行 DM 检验
```

---

## 16.5 小测试样本的限制

如果对齐测试集只有约 54 周：

- Accuracy 每错一个样本变化约 1.85 个百分点；
- AUC 可能对少数样本非常敏感；
- F1 受类别分布影响较大；
- DM 检验统计功效有限；
- 单次时间切分的结论不够稳定。

因此应增加：

- rolling-origin evaluation；
- expanding-window backtesting；
- 多个非重叠测试窗口；
- bootstrap 置信区间；
- 预测差异的实际幅度；
- 危机期与正常期分组结果。

# 17. 推荐的整体模型层级

```text
M0：Naive / Random Walk / Price-only
        ↓
M1：机制化市场、宏观和基本面核心变量
        ↓
M2：M1 + 遥感代理
        ↓
M3：M2 + 航运变量
        ↓
M4：结构化供应链图或完整多模态模型
```

其中：

```text
M0 用于证明模型是否优于简单历史规则；

M1 用于建立经济机制清晰的传统数据基线；

M2 用于检验遥感数据是否提供增量信息；

M3 用于检验航运活动是否提供进一步增量信息；

M4 用于检验显式供应链结构是否优于简单特征拼接。
```

# 18. 当前推荐决策汇总

| 问题 | 推荐决策 |
|---|---|
| 是否加入 M0 | 加入，包括多数类、方向持续性、price-only 和随机游走价格基准 |
| GPR 是否进入 M1 | 保留，视为结构化外部风险指数 |
| M1 使用小核心集还是大候选池 | 核心结果使用固定 10 变量；大候选池动态筛选作为扩展实验 |
| M1 样本是否接受从 2007-08 开始 | 接受，作为最干净的主规格 |
| 是否回填 OVX 和 futures spread | 不做未来回填；VIX 替代仅用于独立稳健性实验 |
| 是否使用 Sentinel-2 | 质量指标可保留，光学机制变量需验证后再进入核心模型 |
| 是否需要机制验证 | 需要，但机制验证不能替代最终预测消融 |
| M3/M4 能否直接与 M1/M2 全样本比较 | 不能，必须同时报告共同样本比较 |
| DM 检验如何进行 | 仅在完全相同测试日期和损失序列上进行 |
| 测试样本较小怎么办 | 使用 rolling-origin、bootstrap 和多个测试窗口提高稳健性 |
