# 3. 当前样本损失问题

## 3.1 问题来源

当前 `data_loader` 使用：

```python
dropna()
```

删除包含缺失值的样本。

但是以下两个核心变量在研究期初期没有数据：

| 变量 | 起始时间 |
|---|---|
| `ovx` | 约 2007-05 |
| `futures_spread` | 约 2007-08 |

由于 M1 要求所有核心变量同时非空，`dropna()` 会删除 2006 年至 2007 年中期的所有周度样本。

---

## 3.2 样本变化

原始研究期包含：

```text
1043 周
```

加入 `ovx` 和 `futures_spread` 并执行完整行 `dropna()` 后，有效样本变为：

```text
957 周
```

因此损失：

```text
1043 - 957 = 86 周
```

M1 的有效样本起点从：

```text
2006-01
```

推迟至：

```text
2007-08
```

损失约 86 周，即约 1 年 8 个月的数据。

---

## 3.3 当前影响

该样本损失本身不一定构成严重问题，因为：

- 整个研究期仍然较长；
- 957 个周度样本仍可用于传统机器学习模型；
- OVX 和期货价差具有明确的经济机制；
- 保留高质量变量可能优于为了早期样本而使用较弱变量。

但需要注意：

- 所有 M1、M2 和 M3 模型可能因此使用相同的较短样本期；
- 如果不同模型或消融组的缺失处理不一致，模型间比较可能不公平；
- `dropna()` 可能删除不仅由 OVX 和期货价差造成的缺失，还会删除其他模态缺失的样本；
- 复杂模型原生支持缺失值时，统一执行 `dropna()` 可能造成不必要的样本损失。

---

## 3.4 建议的处理方案

### 方案 A：统一使用共同完整样本

所有模型和所有模态实验均使用：

```text
2007-08 至研究期结束
```

优点：

- 模型之间具有完全相同的样本；
- 消融实验比较公平；
- 不需要填补 OVX 或期货价差；
- 方法最透明。

缺点：

- 损失约 86 周的数据。

该方案适合作为核心实验。

---

### 方案 B：仅针对模型所需变量执行 `dropna()`

不要对 `weekly_features.csv` 的全部列统一执行：

```python
df.dropna()
```

而应根据当前实验组选择特征后，再针对这些列删除缺失值：

```python
required_cols = feature_cols + [target_col]

model_df = df.dropna(
    subset=required_cols
).copy()
```

这样可以避免因为未进入当前模型的变量存在缺失，而误删有效样本。

---

### 方案 C：按照模型能力处理缺失值

#### Logistic Regression

不原生支持 NaN，需要进行：

- 中位数填补；
- 训练集统计量填补；
- 缺失标记；
- 或限制在完整样本期。

#### Random Forest

如果当前实现不支持 NaN，也需要：

- 中位数填补；
- 常数填补；
- 缺失标记；
- 或完整样本分析。

#### XGBoost

可以原生处理 NaN，因此不需要因为少数变量缺失而删除整个样本。

#### LightGBM

同样可以原生处理 NaN，并学习缺失值的默认分裂方向。

因此可以设计两组实验：

```text
共同完整样本实验：
所有模型均使用 2007-08 之后的样本

模型原生缺失处理实验：
XGBoost 和 LightGBM 保留 NaN
```

---

### 方案 D：使用 VIX 进行早期样本稳健性检验

VIX 的时间覆盖早于 OVX，可以另外构建：

```text
M1-OVX
```

和：

```text
M1-VIX
```

其中：

- M1-OVX 是核心模型；
- M1-VIX 是替代性稳健性模型；
- 不建议将 VIX 和 OVX 同时纳入核心模型；
- 不建议直接用 VIX 回填 OVX 后拼接成同一个原始变量。

为了公平，应首先在共同样本期内比较：

```text
OVX 模型 vs VIX 模型
```

之后再测试 VIX 是否能通过更长样本期改善预测性能。

# 5. 各变量的具体构建方案

## 5.1 `gpr`

### 变量含义

`gpr` 表示地缘政治风险，用于代理：

```text
地缘政治冲突或紧张
        ↓
未来供应中断风险上升
        ↓
石油市场预防性需求增加
        ↓
原油价格与波动率变化
```

### 文献依据

- P076：最重要的外部变量之一；
- P072：支持地缘政治风险对油价预测的作用。

### 数据源

Caldara–Iacoviello Geopolitical Risk Index。

数据文件：

```text
gpr_web.xls
```

通常包括：

- 全球 GPR；
- 历史 GPR；
- 威胁类 GPR；
- 行动类 GPR；
- 国别 GPR。

### 推荐使用

核心 M1 中优先使用：

```text
全球 GPR 指数
```

国别 GPR 可以在后续机制或区域分析中使用，但不必全部进入核心模型。

### 时间处理

GPR 通常是月频变量。

应按照实际发布日期进行周频对齐：

```text
发布日期之前：不可使用本月 GPR
发布日期之后：向前填充最近已发布值
```

不能将某月最终 GPR 值直接赋给该月所有周。

---

## 5.2 `ovx`

### 变量含义

OVX 是原油市场隐含波动率指标，用于代理：

- 石油特定不确定性；
- 原油市场风险预期；
- 预防性需求；
- 期权市场对未来价格波动的预期。

### 文献依据

P052 支持在 OVX 和 VIX 高度相关时优先使用 OVX，因为 OVX 与石油市场机制的对应关系更加直接。

### 数据源

FRED 代码：

```text
OVXCLS
```

### 频率转换

原始数据为日频。

可根据周度预测截止日期构造：

```text
ovx_last
ovx_mean
ovx_max
ovx_change
```

核心模型建议先使用：

```text
上一预测周内 OVX 的均值
```

或：

```text
预测截止日之前最近一个有效交易日的 OVX 收盘值
```

具体选择需要在所有日频市场变量中保持一致。

---

## 5.3 `gold_return`

### 变量含义

黄金收益率用于表示：

- 商品市场共同波动；
- 避险需求；
- 通胀预期；
- 全球风险情绪；
- 原油与贵金属之间的联动。

### 文献依据

P004。

### 数据源

优先选项：

```text
FRED: GOLDPMGBD228NLBM
```

该序列表示 LBMA 黄金价格。

替代数据源：

```text
Yahoo Finance: GC=F
```

### 构建方式

先计算对数价格：

```math
\log(GoldPrice_t)
```

再计算对数收益率：

```math
gold\_return_t
=
\log(GoldPrice_t)
-
\log(GoldPrice_{t-1})
```

周频版本可以使用：

```text
本周最后一个交易日价格
相对于上一周最后一个交易日价格的 log return
```

---

## 5.4 `global_econ_activity`

### 变量含义

全球经济活动用于表示全球原油需求。

经济机制为：

```text
全球经济活动增强
        ↓
工业生产与运输需求上升
        ↓
原油需求增加
        ↓
油价面临上行压力
```

### 文献依据

- P053【强】；
- P052；
- P004；
- P072。

### 数据源选择

#### 首选：Kilian Global Economic Activity Index

数据源：

```text
Dallas Fed
```

特点：

- 与全球大宗商品运输和真实经济活动相关；
- 在石油价格研究中具有明确文献基础；
- 更适合作为全球原油需求代理。

#### 替代：OECD Composite Leading Indicator

FRED 代码：

```text
OECDLOLITOAASTSAM
```

特点：

- 可作为全球经济周期代理；
- 数据获取方便；
- 但与 Kilian 指数的经济含义不完全相同。

#### 其他替代方案

- 全球工业生产；
- 全球制造业 PMI；
- OECD 工业生产；
- CPB World Trade Monitor。

### 选择原则

核心模型只保留一个主要的全球活动指标，避免同时加入多个高度相关的全球需求代理。

## 5.5 `nonoil_industrial_commodity`

### 变量含义

非油工业商品价格用于代理全球工业需求。

经济机制为：

```text
全球制造业与工业活动增强
        ↓
工业原料和金属需求上升
        ↓
非油工业商品价格上涨
        ↓
反映全球需求扩张
```

### 文献依据

- P053【短期预测作用较强】；
- P054。

### 数据源

优先候选：

```text
FRED: PINDUINDEXM
```

表示 IMF 工业原料价格指数。

另一候选：

```text
FRED: PALLMINDEXM
```

也可使用：

- LME 金属指数；
- World Bank Pink Sheet；
- CRB Industrial Materials Index；
- IMF 金属价格指数。

### 变量处理

建议使用：

```text
log difference
```

或：

```text
percentage change
```

而非直接使用可能存在趋势和非平稳性的价格指数水平。

## 5.6 `futures_spread`

### 变量含义

期货—现货价差用于表示：

- 市场紧张程度；
- 当前供需平衡；
- 库存激励；
- 市场对未来价格的预期；
- backwardation 或 contango 状态。

### 文献依据

- P053；
- P054；
- P072。

### 数据源

可选数据源包括：

- ICE Brent futures curve；
- EIA Brent spot price；
- Brent 近月及远月期货；
- 商业数据库中的连续期货合约。

现货价格可以使用：

```text
EIA RBRTE
```

期货价格可以使用：

- ICE Brent front-month；
- ICE Brent 3-month；
- ICE Brent 6-month；
- `BZ=F` 等连续近月序列。

### 构建方式

#### 现货—近月价差

```math
Spread_t
=
Futures_t^{1m}
-
Spot_t
```

#### 近月—远月价差

```math
Spread_t
=
Futures_t^{1m}
-
Futures_t^{6m}
```

#### 相对价差

```math
RelativeSpread_t
=
\frac{Futures_t^{1m}-Futures_t^{6m}}
{Futures_t^{6m}}
```

### 方向解释

若定义为：

```text
近月价格 - 远月价格
```

则：

- 正值通常表示 backwardation；
- 可能反映当前市场偏紧；
- 负值通常表示 contango；
- 可能反映库存充足或当前需求偏弱。

必须在文档中明确价差的计算方向。

---

## 5.7 `commodity_fx`

### 变量含义

商品货币用于表示：

- 全球商品需求；
- 风险偏好；
- 资源出口国贸易条件；
- 美元与大宗商品价格之间的汇率渠道。

### 文献依据

- P053；
- P004。

### 数据源

FRED 候选序列：

```text
DEXCAUS
DEXUSAL
```

分别对应：

- 加拿大元相关汇率；
- 澳大利亚元相关汇率。

使用前必须核对各 FRED 序列的报价方向。

例如：

```text
CAD per USD
```

和：

```text
USD per AUD
```

含义不同，不能直接平均。

### 构建方式

先统一为相同的经济方向，例如：

```text
本币升值 = 指标上升
```

再分别计算：

```math
\Delta FX_t
=
\log(FX_t)-\log(FX_{t-1})
```

可构建一个复合指标：

```math
commodity\_fx_t
=
\frac{
z(CADReturn_t)+z(AUDReturn_t)
}{2}
```

其中所有标准化参数必须仅使用训练集估计。

---

## 5.8 `dgs10_change`

### 变量含义

10 年期国债收益率变化用于表示：

- 利率变化；
- 资金成本；
- 商品持有成本；
- 宏观增长和通胀预期；
- 金融条件变化。

### 文献依据

P076 指出收益率水平可能存在单位根问题，因此采用差分形式。

### 数据来源

已有变量：

```text
treasury_10y
```

无需重新下载。

### 构建方式

若数据已经是周频：

```python
df["dgs10_change"] = df["treasury_10y"].diff()
```

若原始数据是日频，可以先：

1. 取预测截止日前最近一个有效交易日；
2. 转换为周频；
3. 再计算周度差分。

注意收益率的单位通常是百分数，因此：

```text
4.20 → 4.30
```

对应变化为：

```text
0.10 个百分点
```

即 10 个基点。

# 6. 统一时间对齐原则

## 6.1 按实际发布日期对齐

所有变量必须满足：

```math
release\_date \leq prediction\_date
```

模型在时间 `t` 使用的变量只能是：

```math
X_t
=
\text{information available by prediction date }t
```

不能使用预测时点之后才发布的信息。

---

## 6.2 月频变量转周频

以下变量通常为月频：

- `gpr`
- `global_econ_activity`
- `nonoil_industrial_commodity`

正确流程为：

```text
月度统计值
    ↓
确定实际发布日期
    ↓
从发布日期起进入可用信息集
    ↓
向前填充至下一次发布日期
```

错误方式为：

```text
将当月最终值赋给当月所有周
```

这会导致 look-ahead bias。

---

## 6.3 日频变量转周频

日频市场变量包括：

- `ovx`
- 黄金价格；
- CAD/AUD 汇率；
- 10 年期国债收益率；
- Brent 现货和期货价格。

需要先定义固定的预测截止点，例如：

```text
每周五收盘后预测下一周
```

然后只使用截止时间之前的数据。

可选择：

- 周末最后有效值；
- 周均值；
- 周内最大值；
- 周变化率。

同一类型变量应尽量采用一致的聚合规则。

---

## 6.4 入模变量一律滞后

为了预测下一周结果，入模变量必须满足：

```text
使用第 t 周可获得的信息
预测第 t+1 周油价
```

例如：

```text
Feature week: t
Target week: t+1
```

不能在预测下一周方向时，使用下一周结束后才能确定的变量值。

# 7. 推荐的数据处理顺序

```text
Step 1：下载原始变量
    ↓

    ↓
Step 3：清洗异常值和缺失值
    ↓

    ↓

    ↓
Step 6：转换为周频
    ↓
Step 7：构建收益率、差分、价差和复合指标
    ↓
Step 8：生成滞后和移动统计特征
    ↓
Step 9：与 prediction_date 对齐
    ↓
Step 10：进行时序训练、验证和测试切分
```

# 8. 建议的数据质量检查

对每个变量输出以下信息：

| 检查项 | 说明 |
|---|---|
| 起始时间 | 第一条有效记录 |
| 结束时间 | 最后一条有效记录 |
| 原始频率 | 日频、周频或月频 |
| 周频覆盖率 | 有效周数占总周数的比例 |
| 缺失周数 | 周度主表中的缺失数量 |
| 发布时间 | 是否有明确的发布日期 |
| 转换方式 | last、mean、difference、return 或 forward fill |
| 是否滞后 | 是否使用预测时点之前的信息 |
| 单位根检验 | 是否需要差分 |
| 异常值 | 是否存在极端值或结构断点 |

# 10. 最终落地建议

| 阶段 | 建议做法 |
|---|---|
| 核心 M1 | 保留机制化 10 变量 |
| 不确定性变量 | 核心使用 OVX，VIX 仅作替代性稳健性检验 |
| 样本期 | 核心模型可统一从 2007-08 开始 |
| 缺失处理 | 不要对完整主表直接执行无条件 `dropna()` |
| 公平比较 | 所有消融模型优先使用相同的共同样本期 |
| 树模型扩展 | 额外测试 XGBoost/LightGBM 原生处理 NaN 的结果 |
| 月频变量 | 按发布日期前向填充，不按统计月份回填 |
| 日频变量 | 按固定预测截止时间聚合 |
| 滞后处理 | 所有特征仅使用预测时点之前可获得的信息 |
| 解释分析 | 使用 SHAP 时注意相关变量间的贡献分摊 |
| 稳健性 | 运行 OVX→VIX 替换、不同样本期和不同缺失处理实验 |
