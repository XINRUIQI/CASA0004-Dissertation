# 第三部分：Multimodal Forecasting / Event-aware Oil Price Prediction 数据说明

## 1. 第三部分是干嘛的？

这一部分主要服务于你的 dissertation 里的 **multimodal forecasting / event-aware oil price prediction**。

你的核心价格数据可能是 Brent / WTI / futures / macro / shipping / satellite 等，但这些数据很多是数值型、连续型的。新闻和公司公告的作用是补充：

| 类型 | 作用 |
|---|---|
| 全球事件数据 | 捕捉战争、制裁、冲突、事故、运输中断等外部冲击 |
| 公司公告 | 捕捉 BP、Shell、TotalEnergies、Aramco 等能源公司的停产、项目、维护、投资、财报、产能变化 |
| 文本数据 | 用 NLP 提取情绪、主题、风险关键词、供应冲击信号 |
| 时间戳数据 | 把新闻事件按日期对齐到 daily / weekly oil price dataset |

所以它不是单独用来预测价格，而是转成特征之后加入模型，例如：

```text
Brent price prediction features =
price history
+ macro variables
+ shipping / AIS indicators
+ company news sentiment
+ geopolitical shock dummies
+ supply disruption event counts
```

## 2. 每个 dataset 的作用是什么？

### 3.1 GDELT Event Database

它的作用：**全球宏观事件冲击变量**。

GDELT 是最适合做“全球事件背景”的数据。它覆盖全球新闻事件，历史数据从 1979 年开始，并持续更新；官网说明其全球新闻监测会定期更新，主站说明历史档案可追溯到 1979 年并每 15 分钟更新。

在你的项目里，它可以用来构造：

| 可构造变量 | 例子 |
|---|---|
| geopolitical shock dummy | 某天是否发生重大冲突、制裁、军事行动 |
| conflict intensity | 某地区冲突事件数量 |
| sanction intensity | 涉及 sanctions / embargo 的事件数量 |
| transport disruption signal | 港口、航道、运输相关事件 |
| regional risk index | Middle East / Red Sea / Russia / Gulf 等区域风险强度 |
| tone / sentiment | 新闻整体语气是否偏负面 |

它更偏 **宏观外部冲击**，不是公司层面的运营数据。

你需要注意：  
GDELT 很大、很杂、噪声很高，不能直接全量放进模型。你之后应该只筛选和 oil market 相关的事件类型，例如：

- war / conflict
- sanctions
- embargo
- explosion
- accident
- strike
- transport disruption
- pipeline disruption
- shipping route disruption

### 3.2 BP Press Releases

它的作用：**BP 公司层面的供应、项目、财务和运营信号**。

BP 官网 press releases 页面说明可以浏览自 2010 年以来的 bp 全球 press releases，并可按 topic、region 或 date 筛选。

它在你项目里可以用于：

| 可提取内容 | 对 oil price prediction 的意义 |
|---|---|
| shutdown / maintenance | 可能表示短期供应减少 |
| new project / production start | 可能表示未来供应增加 |
| refinery / upstream update | 反映能源供应链变化 |
| financial results | 反映公司运营状态和市场预期 |
| region / asset names | 可定位到 Gulf, North Sea, US, Azerbaijan 等区域 |
| risk words | “outage”, “incident”, “delay”, “force majeure”等 |

BP 的优势是数量多、结构相对稳定。你的表里原来写 “2010 -- present” 是合理的，因为 BP 官方页面本身也写的是 since 2010。

## 4. 基础设施类别筛选

| CATEGORY | 是否保留 | 原因 |
|---|---|---|
| CRUDE OIL REFINERIES | 保留，核心 | 炼厂节点，和原油需求、加工能力、供应链中断有关 |
| PETROLEUM TERMINALS | 保留，核心 | 油品/原油终端，适合连接港口、航运和储运活动 |
| LNG FACILITIES | 保留，可选核心 | 虽然偏天然气，但能源基础设施和航运/终端活动相关 |
| OFFSHORE PLATFORMS | 保留，核心 | 海上生产节点，适合做供应端/遥感/AIS附近活动 |
| GATHERING AND PROCESSING | 保留，核心 | 上游处理设施，适合作为油气生产链节点 |
| TANK BATTERIES | 保留，可选 | 储油/集输节点，但数量可能较多，可先保留再筛 |
| NATURAL GAS COMPRESSOR STATIONS | 可选 | 偏天然气；如果做 oil + gas infrastructure graph 可以保留 |
| OIL AND NATURAL GAS PIPELINES | 暂时不建议全保留 | 数量可能很大，且线性网络点位处理复杂 |
| OIL AND NATURAL GAS WELLS | 第一轮不保留 | 数量巨大，很多是 dry/abandoned，对油价预测噪音大 |
| NATURAL GAS FLARING DETECTIONS | 可选，不建议第一轮 | 更适合 methane/emissions 项目，不是油价主变量 |
| INJECTION AND DISPOSAL | 不保留 | 注入/废弃处置类，和油价关系较弱 |
| EQUIPMENT AND COMPONENTS | 不保留 | 太零散，空间节点意义弱 |
| STATIONS - OTHER | 不保留 | 类别不清晰，噪音大 |

## 6. 遥感数据流水线状态检查结果

检查结果：遥感数据流水线状态

三个遥感数据源的月度 AOI 指标 **均已构建完成**，且已对齐至周频油价。以下是详细情况：

---

### 一、三个遥感数据源及其 AOI 指标

| 数据源 | 时间范围 | 提取指标 |
|---|---|---|
| Sentinel-2 `(COPERNICUS/S2_SR_HARMONIZED)` | 2017-04 ~ 2025-12 | NDVI, NDWI, NDBI, BSI（均值 + 月内标准差）+ 有效观测数 |
| Landsat `(L5/L7/L8，回填 S2 之前)` | 2006-01 ~ 2017-03 | NDVI, NDWI, NDBI, BSI（仅均值，无月内 std）+ 有效观测数 |

覆盖 8 个 AOI（P001–P008）：Rotterdam、Fujairah、Ras Tanura、Singapore、Houston、Ningbo-Zhoushan、Jamnagar、Basra。

### 三、对齐至周频油价：已实现

核心脚本 `04_code/scripts/aggregate_remote_sensing_to_weekly.py` 完成了：

1. Landsat + Sentinel-2 纵向拼接（`sensor_flag` 区分）
2. 光学 + VIIRS 按月合并
3. Long → Wide 透视（列名如 `opt_NDVI_P001`、`ntl_ntl_avg_rad_mean_P003`）
4. 月度 → 周频：`resample("D").ffill()` → `resample("W-FRI").last()`（前向填充，周五截止）

输出 `03_data/processed/weekly_remote_sensing_features.csv`（112 列，1041 周），并已通过 `build_feature_matrix.py` 合并进 `weekly_features.csv`。

---

### 四、注意事项 / 潜在缺口

1. VIIRS 实际起始偏晚：脚本设 2012，但数据实际从 2014-01 才有值
2. Landsat 缺少月内标准差：S2 有 `NDVI_std` 等，Landsat 没有（合并后这些列为 NaN）
3. 末尾时间不齐：`weekly_remote_sensing_features.csv` 末周为 2025-12-05，而 `weekly_time_index.csv` 到 2025-12-26（月度 resample 边界问题）
4. 云致缺失：部分 AOI/月份因云覆盖存在空值（如 Landsat 早期的 P001、P003）
5. Notebook 仅文档：实际月度指标构建和周频对齐都在 Python 脚本中完成，`Dataset Overview` notebook 是纯 Markdown 规划文档，未包含执行代码

## 7. 三家公司的 Investor Reports 页面对比

### BP — 最值得手动下载

页面：`Archive of results, reports and presentations`

- 时间覆盖：2005–2026，按年份+季度整齐排列，最长的历史
- 每季度提供的下载：
  - `Stock exchange announcement` (= 季度 press release，PDF) — **下这个**
  - `Group databook` (XLSX) — 结构化数据，可选
  - `Presentation slides + script` (PDF) — 可选
  - `Q&A transcript` (PDF) — 可选
- 手动工作量估算：2005–2026 = ~84 个季度。如果只下 press release，就是 **84 个 PDF**，每个页面点一次，大约 30–40 分钟
- 另外还有每年一份 Annual Report（~21 份）

---

### Shell — 中等难度

页面：`Quarterly Results`

- `Historical Quarterly Results` 部分有历史季度，但页面上目前可见的需要滚动确认
- 每季度提供：
  - `Quarterly press release` (PDF) — **下这个**
  - `Quarterly unaudited results` (PDF) — 可选
  - `Quarterly databook` (XLSX) — 可选
  - `Quarterly slides` (PDF) — 可选
- 问题：Shell 的 PDF URL 是 JCR 动态路径（极长），不容易猜测，手动下载必须从页面逐个点击
- 手动工作量估算：取决于历史数据回溯多远。如果 2015–2026 约 **44 个季度 press releases**

---

### TotalEnergies — 页面最友好

页面：`Investor presentations`

- 按年份分组的表格，每行有 `Press release | Presentation | Replay` 三列，直接点链接下载
- 覆盖年份可见：2019/2020–2026
- 手动工作量估算：约 **24–28 个季度 press releases**，页面结构清晰，10–15 分钟搞定
- 另外 `Reports` 页面有 URD (Universal Registration Document) = 年报，2019–2025 约 7 份
