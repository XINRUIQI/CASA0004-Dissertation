## 0. M0 — 基准线（随机游走 / 不变预测）

**M0 是不含任何特征的"朴素基准"层**，作为衡量 M1–M4 是否真正有预测能力的**地板（floor）**。任何模型只有显著优于 M0，才说明其特征带来了真实信息增益，而非仅靠序列自身的持续性。

| target | M0 基准 | 定义 |
| --- | --- | --- |
| price（油价） | **随机游走 / 不变预测（no-change）** | `ŷ(t+1) = y(t)`，即用本周价格预测下周价格 |
| volatility（波动率） | **朴素持续 / 滚动均值** | `ŷ(t+1) = vol(t)`（或过去 N 周均值） |
| direction（涨跌方向） | **多数类 / 持续方向** | 恒预测训练集多数类；或 `ŷ(t+1) = sign(Δy(t))`（延续上周方向） |

**为什么必须有 M0**

- **price 的高 R² 有迷惑性**：油价高度持续，随机游走本身就能取得很高的 R²。M1 的 price R²≈0.867 看似很好，但若不与随机游走相比，无法判断模型是否真的"预测"了价格，还是只是复制了上一期值（见 `M1_pipeline.md` §7 caveat）。
- **direction 需对比随机/多数类**：三分类（down/flat/up）的随机基线 ≈ 0.33–0.45，多数类基线可能更高。M1–M4 的 accuracy 多在 0.42–0.56，须对照 M0 才知是否有效。

**正确的对比指标（相对 M0）**

- **相对随机游走的样本外 R²（OOS-R²）**：`1 − MSE(model) / MSE(RW)`，>0 才说明优于随机游走。
- **Diebold–Mariano（DM）检验**：检验模型与 M0 的预测误差差异是否统计显著。
- ⚠️ DM 检验与跨层对比都须在**对齐的同一时间窗口**上进行（见第 2 节末 caveat）。

> **当前状态**：M0（随机游走 / 不变预测）**尚未纳入结果表**，是 `M1_pipeline.md` §7 列出的待办项。下文第 3 节的 M1–M4 结果须在补齐 M0 后，以"相对 M0 的 OOS-R² + DM 检验"重新解读，不能仅看绝对 R²/accuracy。

## 2. 变量分层定义

层级是**累加**关系：`M2 = M1 + 遥感`，`M3 = M1 + 航运`，`M4 = M1 + 遥感 + 航运`。

### M1 — 金融/市场/宏观基线（10 个，机制化）


| #   | 变量                            | 经济机制                |
| --- | ----------------------------- | ------------------- |
| 1   | `brent_price`                 | 油价自身动态（lags/ma/mom） |
| 2   | `crude_stocks_change`         | 供给 / 市场平衡           |
| 3   | `global_econ_activity`        | 全球需求（Kilian REA）    |
| 4   | `nonoil_industrial_commodity` | 全球需求（工业原料）          |
| 5   | `futures_spread`              | 市场紧张 / 预期           |
| 6   | `ovx`                         | 石油特定不确定性（优先 VIX）    |
| 7   | `gpr`                         | 预防性需求（地缘政治风险）       |
| 8   | `dgs10_change`                | 利率 / 持有成本（ΔDGS10）   |
| 9   | `gold_return`                 | 商品联动 / 避险           |
| 10  | `commodity_fx`                | 汇率渠道（CAD/AUD）       |


**派生特征（LAG_MA_SPECS）**：对部分基础变量动态构造三类时序特征（均在周频 W-FRI 上、用过去值，避免泄漏）：

- **lag-k（滞后）**：取 t−k 周的值，`x_lag{k} = x(t−k)`。
- **ma-w（移动平均）**：过去 w 周均值，`x_ma{w} = mean(x(t−w+1 … t))`。
- **mom-w（动量）**：相对 w 周前的变化，`x_mom{w} = x(t) − x(t−w)`。

各变量的具体配置：


| 变量                    | lag        | ma        | mom         |
| --------------------- | ---------- | --------- | ----------- |
| `brent_price`         | lag1, lag4 | ma4, ma12 | mom4, mom12 |
| `ovx`                 | lag1       | ma4       | —           |
| `futures_spread`      | lag1       | ma4       | —           |
| `gpr`                 | lag1       | ma4       | —           |
| `dgs10_change`        | lag1       | —         | —           |
| `crude_stocks_change` | —          | ma4       | —           |
| `commodity_fx`        | —          | ma4       | —           |
| `gold_return`         | —          | ma4       | —           |


> 即 `brent_price` 取 1/4 周滞后、4/12 周均线与动量以承载"价格滞后+收益率"信息；其余变量按其经济属性只补充必要的短期滞后/均线。完整定义见 `config.py` 的 `LAG_MA_SPECS`。

### M2 增量 — 夜间灯光遥感（12 个，4 个石油核心 AOI）

精读后清洗版：用**动态 NTL 异常**（而非原始辐射值）+ **观测质量变量**，覆盖四个石油核心 AOI。
四个 AOI：Rotterdam（进口/炼化枢纽）、Fujairah（离岸油轮主导储油）、Ras Tanura（原油出口码头）、US Gulf（休斯顿 / 美湾储油带）。
完整 11-AOI 面板见 `feature_groups.json["M2_rs_clean"]` / `weekly_m2_clean_features.csv`。


| 变量（× 4 AOI）             | 个数  | 含义                                     |
| ----------------------- | --- | -------------------------------------- |
| `ntl_anomaly_`*         | 4   | 夜间灯光**异常**（去季节/趋势后的动态偏离，代理活动强度变化）      |
| `ntl_valid_obs_count_`* | 4   | VIIRS **有效观测天数**（数据质量 / 可信度控制）         |
| `s2_cloud_fraction_`*   | 4   | Sentinel-2 **云量占比**（光学信息可得性，云越多有效信息越少） |


> `*` 表示后缀为 4 个 AOI：`rotterdam` / `fujairah` / `ras_tanura` / `us_gulf`。

**机制验证（如何证明 NTL 异常确实在反映石油活动）**

思路：NTL 异常只是活动的**遥感代理**，需用独立的"地面真值"经济量交叉验证——若 NTL 异常与这些物理吞吐/库存/炼厂指标在对应 AOI 上同向且显著相关，则说明信号有机制依据。


| 机制维度        | 地面真值变量（验证基准）                                                               | 来源 / 所在层                                 |
| ----------- | -------------------------------------------------------------------------- | ---------------------------------------- |
| 油轮总运力       | `pw_{choke}_capacity_tanker`                                               | PortWatch（M3）                            |
| 港口吞吐 / 进出口量 | PortWatch 港口级 `export/import_tanker`；EIA `crude_imports` / `crude_exports` | PortWatch；EIA（在 `weekly_time_index.csv`） |
| 官方库存变化      | `crude_stocks_change`                                                      | EIA（M1）                                  |
| 炼厂活动        | `refinery_crude_input` / `refinery_utilisation`                            | EIA（在 `weekly_time_index.csv`，目前未进主表）    |


> 验证方式：在各 AOI 上计算 NTL 异常与上述基准的（滞后）相关 / 回归，并对比有效观测数高/低样本的差异（质量控制），确认相关性不是由缺测或云量噪声驱动。

**为什么是 4 个 AOI 而不是 11 个？**

- **石油机制清晰**：4 个核心 AOI 各对应一类明确的石油功能区——Rotterdam（进口/炼化枢纽）、Fujairah（离岸油轮主导储油）、Ras Tanura（原油出口码头）、US Gulf（休斯顿/美湾储油带），覆盖"进口—储存—出口—炼化"全链条，与油价机制直接挂钩。
- **信号质量与噪声权衡**：其余 AOI 或灯光受非石油城市活动干扰大、或缺测/云量严重、或体量小信号弱，纳入会稀释信噪比并增加共线性。
- **可验证性**：4 个核心 AOI 都能找到对应的地面真值（PortWatch 港口吞吐 / EIA 进出口库存），便于做上面的机制验证；部分 AOI 缺乏可对照的吞吐数据。
- **完整 11-AOI 留作 robustness**：全量面板见 `feature_groups.json["M2_rs_clean"]` / `weekly_m2_clean_features.csv`，作为稳健性检验而非主设定。

### M3 增量 — 航运（19 个）

按经济维度组织：油轮专属的流量强度 + DWT 运力加权 + 平均船型 + 全局汇总 + 进出口方向不对称 + GFW 滞留拥堵代理。
数据源：PortWatch（2019+）、Global Fishing Watch / AIS（2012+）。
**咽喉点数量：3 个**——霍尔木兹（Hormuz）、苏伊士（Suez）、马六甲（Malacca）；另含 `pw_all_`* / `gfw_all_`* 两个跨全部咽喉点的全局汇总。

#### (a) PortWatch 咽喉点油轮通行量（10 个）

每个咽喉点（hormuz / suez / malacca）各 3 个 + 1 个全局汇总：


| 变量（× 3 咽喉点）            | 个数  | 含义                |
| ---------------------- | --- | ----------------- |
| `pw_*_n_tanker`        | 3   | 油轮通行**艘次**        |
| `pw_*_capacity_tanker` | 3   | **DWT 运力**加权通行量   |
| `pw_*_avg_tanker_size` | 3   | 油轮**平均船型尺寸**      |
| `pw_all_n_tanker_sum`  | 1   | 全部咽喉点油轮艘次**全局汇总** |


#### (b) PortWatch 进出口方向不对称（2 个，方向性）


| 变量                       | 含义                                       |
| ------------------------ | ---------------------------------------- |
| `pw_tanker_exp_imp_asym` | 进出口不对称指数 =（出口枢纽 − 进口枢纽）/（两者之和），∈ [-1, 1] |
| `pw_tanker_exp_imp_net`  | 进出口净量 = 出口枢纽装载 − 进口枢纽卸载（吨）               |


#### (c) GFW / AIS 船舶停留活动与拥堵代理（7 个，2012+）

每个咽喉点（hormuz / suez / malacca）各 2 个 + 1 个全局汇总：


| 变量（× 3 咽喉点）                    | 个数  | 含义                                   |
| ------------------------------ | --- | ------------------------------------ |
| `gfw_*_total_hours`            | 3   | AIS 船舶**活动总时长**（活动强度）                |
| `gfw_*_dwell_hours_per_vessel` | 3   | **单船滞留时长**（拥堵 / dwell 代理 = 总时长 / 船数） |
| `gfw_all_total_hours_sum`      | 1   | 全部咽喉点 AIS 活动总时长**全局汇总**              |


**为什么只选这 3 个咽喉点，而不是 6 个？**

- **油运相关性最高**：霍尔木兹、苏伊士、马六甲是全球原油/成品油海运量最大的几条要道（霍尔木兹约占全球海运石油的 ~1/5），覆盖驶往欧洲与亚洲主要进口市场的绝大部分油轮流量，与 Brent 定价最相关。
- **机制清晰、避免噪声**：其余咽喉点对油价机制偏间接——巴拿马运河以集装箱/LNG/谷物为主、土耳其海峡体量小、好望角多为绕行替代路线——纳入会稀释油轮信号并增加共线性与缺测。
- **数据质量与对齐**：聚焦 3 条主航道可保证 PortWatch（通行量）与 GFW（AIS 停留）两套数据在这些点上覆盖完整、口径一致，便于相互印证；其它通道由 `pw_all_`* / `gfw_all_*` 全局汇总兜底。
- **与图结构一致**：这 3 个咽喉点正是 ST-GNN 边定义（`config.py` 的 `CHOKEPOINT_EDGES` 中 hormuz/suez/malacca）所用，变量与拓扑对应。

**机制验证（如何证明航运变量确实在反映石油供给/物流）**

思路：PortWatch 通行量与 GFW 停留都是船舶活动的代理，需用独立的"地面真值"——海运进出口量、运价、官方供给指标——交叉验证；若两套数据相互印证、且与这些基准同向显著相关，则说明信号有机制依据。


| 机制维度              | 地面真值变量（验证基准）                                                               | 来源 / 所在层                                     |
| ----------------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| 通行量 vs 停留（两套数据互证） | `pw_{choke}_n_tanker` ↔ `gfw_{choke}_total_hours`                          | PortWatch ↔ GFW（M3 内部互证）                     |
| 海运进出口量            | EIA `crude_imports` / `crude_exports`；PortWatch 港口级 `export/import_tanker` | EIA（在 `weekly_time_index.csv`）；PortWatch（M3） |
| 拥堵 / 运价           | 单船滞留 `gfw_{choke}_dwell_hours_per_vessel` ↔ 油轮运价指数（BDTI/TD3，外部，目前未进主表）     | GFW（M3）↔ 外部运价                                |
| 官方供给 / 库存         | `crude_stocks_change`、`crude_production`（EIA）                              | EIA（M1 / 在 `weekly_time_index.csv`）          |


> 验证方式：在各咽喉点上计算通行量/运力与 EIA 海运进出口的（滞后）相关；用 PortWatch ↔ GFW 互证排除单源缺测；并检验地缘事件期（如霍尔木兹紧张）滞留时长是否随运价同步上升。
